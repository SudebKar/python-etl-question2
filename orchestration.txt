scheduled_process_job.py
from src.services.process_trigger_service import ProcessTriggerService
from src.services.dependency_resolver_service import DependencyResolverService


class ScheduledProcessJob:

    @staticmethod
    def execute(process_id: str):
        """
        Entry point for scheduled job execution.
        """

        can_run = DependencyResolverService.can_run(process_id)

        if not can_run:
            # Dependency not met — do nothing, scheduler will retry later
            return

        ProcessTriggerService.trigger_process(
            process_id=process_id,
            run_type="scheduled"
        )


Why this is correct

Scheduler retries naturally

No sleep / wait / polling

Dependency logic is centralized

This mimics Autosys “box job” behavior.

2️⃣ StatusMonitorJob

Purpose:
Track running jobs and update their state.

This job:

scans STARTED runs

polls FastAPI

updates DB

enables downstream dependencies

status_monitor_job.py
from sqlmodel import select
from src.db.session import get_session
from src.models.scheduler_run_state import SchedulerRunState
from src.services.process_status_service import ProcessStatusService


class StatusMonitorJob:

    @staticmethod
    def execute():
        """
        Polls all running processes and refreshes their status.
        """

        with get_session() as session:
            stmt = select(SchedulerRunState).where(
                SchedulerRunState.status == "STARTED"
            )

            running_jobs = session.exec(stmt).all()

        for job in running_jobs:
            try:
                ProcessStatusService.refresh_run_status(job.run_id)
            except Exception:
                # Intentionally swallow exceptions
                # Next run will retry
                continue


Blunt truth:
Schedulers must be forgiving, not fragile.
Crashing here would be a design failure.
