1️⃣ job_registry.py

Purpose:
Translate DB schedules → APScheduler jobs.

This keeps scheduler.py dumb.

job_registry.py
from apscheduler.triggers.cron import CronTrigger
from src.repositories.schedule_repository import ScheduleRepository
from src.jobs.scheduled_process_job import ScheduledProcessJob


class JobRegistry:

    @staticmethod
    def register_jobs(scheduler):
        """
        Reads schedules from DB and registers them with APScheduler.
        """

        schedules = ScheduleRepository.get_active_schedules()

        for sched in schedules:
            if sched.schedule_type != "CRON":
                continue  # event-based comes later

            trigger = CronTrigger.from_crontab(sched.cron_expression)

            scheduler.add_job(
                func=ScheduledProcessJob.execute,
                trigger=trigger,
                args=[sched.process_id],
                id=str(sched.job_id),
                replace_existing=True,
                max_instances=1,
                misfire_grace_time=300
            )

Why this design is solid

DB is the source of truth

Scheduler restart = clean rehydration

No hardcoded schedules

Ops can enable/disable via DB

2️⃣ scheduler.py

Purpose:
Bootstrap APScheduler and start background jobs.

This file should be boringly short.

scheduler.py
from apscheduler.schedulers.background import BackgroundScheduler
from src.core.job_registry import JobRegistry
from src.jobs.status_monitor_job import StatusMonitorJob


def start_scheduler():
    scheduler = BackgroundScheduler(
        job_defaults={
            "coalesce": True,
            "max_instances": 1
        }
    )

    # Register scheduled pipeline jobs
    JobRegistry.register_jobs(scheduler)

    # Register status monitor (every 1 minute)
    scheduler.add_job(
        func=StatusMonitorJob.execute,
        trigger="interval",
        minutes=1,
        id="status_monitor",
        replace_existing=True
    )

    scheduler.start()

    return scheduler

How this plugs into runtime (important)

You will call start_scheduler() from exactly one place:

Either:

a standalone main.py for scheduler service

Or:

if __name__ == "__main__":

⚠️ Do NOT start APScheduler inside FastAPI lifecycle hooks.
That’s how people accidentally start N schedulers per pod.

Current architecture state (checkpoint)

You now have:

Stateless FastAPI execution service

Durable scheduler metadata

APScheduler as a thin trigger engine

Clean separation of concerns

Restart-safe scheduling

This is already better than many Airflow deployments.
